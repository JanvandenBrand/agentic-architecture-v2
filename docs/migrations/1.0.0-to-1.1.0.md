# Schema 1.0.0 and 1.1.0 compatibility

## What changes

Tool package `1.2.0` supports both schema versions. New cases use `1.1.0`; existing `1.0.0` cases remain
readable and keep their original records. Lifecycle `2.1.0` adds host/model policy without changing the
phase route, owners, review sequence, or human gates.

## Existing case owners

No case conversion is required or supported. Keep the original files, hashes, and signatures.
Continue the case on GitHub Copilot with schema `1.0.0`:

```powershell
npm ci --no-audit --no-fund
npm run validate -- --case cases\<existing-case>
```

Do not edit `schemaVersion` to upgrade signed evidence. Such a change alters the signed payload and
can invalidate downstream hash bindings.

## New case owners

Start with `1.1.0` and confirm one host in Phase 0: `github-copilot` or `claude-code`. Record it in the
model plan and every journal event. Use that host for the whole case. Model substitutions need an
explicit human decision reference; they are not permission to switch hosts.

Claude's live workflow remains unqualified until the [host qualification procedure](../claude-code.md#live-host-qualification)
passes. The offline matrix is:

```powershell
npm run smoke:contoso
npm run smoke:contoso -- --host github-copilot --schema-version 1.1.0
npm run smoke:contoso -- --host claude-code --schema-version 1.1.0
```

All three runs are synthetic and make no live model calls or Azure changes.

## Rollback and safe stop

- An older tool that only understands `1.0.0` cannot continue a `1.1.0` case.
- Keep the compatible tool release with the case. If it is unavailable, stop rather than change record
  versions or fabricate replacement evidence.
- Returning to an older tool for an unchanged `1.0.0` case does not require rewriting the case.
- Unknown versions, mixed versions, missing host information, or a changed host are validation errors.

This change does not enable the uncatalogued authorisations for optional phases 7 and 8, resolve other
pre-existing audit findings, or authorise deployment.
